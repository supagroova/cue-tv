# Parallel

Use only when the user explicitly requests delegation/parallel work. Inherit the active model and use available tools; do not import provider aliases or pretend same-model lenses are model diversity. Name each worker's objective, permitted files, inputs/interfaces, evidence, stop conditions and write ownership. Reviewers report only; the coordinator integrates and verifies.

Use isolated branches/worktrees where a real checkout exists. DerivedData, cache directories, fixture services, simulator and physical Apple TV are shared resources unless separately allocated. Serialize device/install/signing work and integration. No two workers edit the same file. For an arena compare candidates against the same acceptance fixtures, select one and port only justified improvements; do not merge every abstraction. Drain workers and aggregate failures as well as successes. Delegation never weakens tests, authorization or evidence requirements.

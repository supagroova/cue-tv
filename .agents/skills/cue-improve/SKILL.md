# Improve

Use the current conversation's relevant facts and durable task evidence. Never guess the active transcript or scrape other sessions. Separate recurring defects from one-off preferences. Prefer simpler ownership/types, then an executable check with a useful error, then a regression test, then concise guidance.

For each proposed improvement name evidence, scope, false-positive risk and enforcement limit. Test a synthetic or historical bad case and an allowed case. Do not turn a lesson into a global ban, arbitrary coverage threshold or new approval ritual. A reflection-only request yields proposals; an explicit request to improve the harness authorizes scoped local edits. No edits to global provider configuration or forwarding code to a second provider. Update the enforcement table and porting notes when mechanics change.

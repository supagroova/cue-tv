# Phase 1 — embedded torrent transport

Status: controlled-peer simulator playback verified; phase acceptance still in progress.

The tvOS app links an embedded librqbit Rust static library. A debug lab action starts a fresh torrent session in the app sandbox, selects file index 0 and plays an unguessable loopback HTTP endpoint through AVPlayer. Native work runs on a two-thread Tokio runtime. C handles are IDs, request/snapshot envelopes are versioned, snapshots include session identity and byte counters, snapshot strings have explicit allocation/free ownership, and stopping invalidates the handle and cancels transfer. The Swift owner rejects stale polling results after stop/restart. Dismissing or backgrounding the lab stops player and transport.

The current fixture peer is a separate local seeder on the development Mac, solely to supply generated test content. The app performs the download and stream adaptation itself. This does not introduce a production backend requirement. The bridge also accepts validated v1 magnets and has separate opt-in tracker and DHT discovery settings with DHT persistence disabled. Magnet metadata resolution and multi-file selection are tested against known peers; internet discovery remains unverified.

## Reproduce

Install Rust 1.100.0 and the `aarch64-apple-tvos` and `aarch64-apple-tvos-sim` targets. Xcode and XcodeGen are also required. Native dependencies use a pinned git revision and Cargo.lock. See `native/cue-torrent/NOTICE.md` for the narrow tvOS socket patch.

Run `cargo +1.100.0 test --locked --manifest-path native/cue-torrent/Cargo.toml`. In another terminal run `cargo +1.100.0 run --locked --manifest-path native/cue-torrent/Cargo.toml --example seed`, then `make apple-lab-test DESTINATION='platform=tvOS Simulator,id=YOUR_SIMULATOR_ID'`. CI starts and stops its own fixture seeder.

## Evidence

- Native byte-range boundary and two C ABI invalid-input/idempotent-stop tests pass. Invalid file-index and unsafe-path tests verify rejection leaves the output directory empty.
- Six real peer integration tests pass (torrent file, magnet metadata resolution, second-episode selection, isolated HTTP tracker, UDP tracker and DHT discovery with no initial peer addresses): empty download directory, separate seeder, suffix request first, HEAD, invalid range (416), full file byte comparison, endpoint unavailable after stop. Deadline is 45 seconds.
- A 64 MiB generated byte fixture, throttled to 64 KiB/s, verifies two not-yet-cached range reads while the file remains incomplete, followed by stopping an open response within two seconds. The test initially failed because an open body outlived session stop; the body now observes the session cancellation token. This is transport evidence, not a ten-minute video playback measurement.
- Seven existing/fixture Swift unit tests pass with the Rust library linked.
- Two tvOS simulator UI tests pass: local decoder start/stop and direct torrent fixture playback clock advancing beyond 0.5 seconds. Simulator runtime is tvOS 26.5.
- Full app, including the final Rust bridge, builds unsigned for the Apple TV device target.

These short deterministic tests do not establish sustained playback, discovery, uncached long seeks, bounded cache, restart stress or hardware qualification. Remaining Phase 1 acceptance: isolated HTTPS tracker and public swarm discovery, repeated cancellation/error stress and performance qualification. Later phases must not treat this proof as completion of those gates.

## Sustained simulator run

Generate the optional twelve-minute control with `python3 scripts/fixtures/generate-long.py`, then start the fixture seeder with `CUE_LONG_FIXTURE=1` and run `make apple-long-test DESTINATION='platform=tvOS Simulator,id=YOUR_SIMULATOR_ID'`. Media remains in `.agent-work/long-playback`; only generated torrent metadata is bundled for this test. The seeder limits upload to 64 KiB/s. The test requires initial playback progress before all bytes are verified and then a playback clock of at least 600 seconds. It retains screenshots and byte-counter evidence in the xcresult. CI runs this test automatically after the shorter lab tests.

The first local run passed on tvOS 26.5 simulator: playback progress began at 403,730 / 9,677,074 verified bytes (about 4.2%), then reached 600 seconds. Total UI-test wall time was 686.606 seconds, including startup and buffering. This is not a claim of stall-free playback or the final 20-second startup target. Evidence: `.agent-work/DerivedData/Logs/Test/Test-SittingRoomTV-2026.11.17_11-20-15-+0100.xcresult`. This measures a constrained MP4 path and does not establish the production media matrix, public swarm independence or hardware performance thresholds.
